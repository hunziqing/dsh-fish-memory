# 阶段五：情绪时序、临时回应需要与条件交流模式

本阶段扩展阶段四后台候选，保存有依据的情绪、意图、局部回应需要和长期交流模式。前台角色自然安慰与实际对话效果，仍需阶段八接入聊天页面后联调；测试不访问真实模型。

## 解释逐步修订

经历 interpretations 区分 emotion、intent、response_need。模型只提供紧凑字段和 episode.evidence 的索引；服务绑定用户身份、作用域、表达消息和正式证据 ID，继续通过阶段一完整语义守卫。

每项分别保存 felt_time、expressed_at、basis_kind、status 和回溯依据。未知感受时间保持 unknown；后来的情绪不自动倒填前文。明确回顾过去须标 retrospective 并给用户证据。“去年害怕、现在不怕”保留为不同感受，不能以现在的状态否认过去。

重新理解旧话时，replaces_id 指向先前解释。旧解释标 corrected、指向当前有效替代；连续多次纠正会追平替代指向，旧修订继续完整保存。默认召回隐藏 corrected，详情历史保留纠正链。不能用 context_inferred 替代 user_confirmed；明确的新用户证据才能纠正已确认理解。助手自己的判断仍不能作为用户确认的依据。

这属于可核验的结构与来源保证。系统不会从 schema 自动证明一句话的真实感受、反讽或指代；label 是否准确仍需要真实样本评估和用户纠错。

## 本次回应需要

经历最新有效 response_need 解释会镜像成独立 response_need 记录，与经历在同一事务中创建或修订。两者使用相同内容、证据、依据类型和确认状态，后续“现在可以给建议”沿用原记录 ID。作用域仍为对应经历，不会扩大成 companion 长期规则。

为避免历史需要一直支配对话，默认召回还要求：

- 证据来自当前会话和 main 分支；距连续已接收水位不超过 6 回合。
- 证据的实际表达时间距当前服务时钟不超过 12 小时，重复扫描或镜像修订不延长它。
- episode 范围的需要，其经历当前有效且未 closed，并与当前 query/真实近期用户上下文有文字话题匹配。
- conversation 范围的手动需要只在该会话适用，仍受回合与时间限制。

这些是首版可检验的保守启发式，不宣称精确识别每次话题结束。改变阈值或引入语义话题状态时需保留上述反串扰测试。历史需要仍在数据库和修订中，不因停止作为当前需要而丢失。

临时需要与长期交流偏好合计最多返回两项，计入总条数和总字符预算。临时需要优先，其后为适用的明确偏好和有条件观察。

## 长期习惯与反例

explicit_preference 表示用户明确的长期要求。后台发布时要求本次真实原话中存在“以后、每次、一直、通常、总是、习惯、长期、平时、请记住”等长期范围线索；单独“这次只想说说”不能发布为永久偏好。该词面门槛只能阻止明显的单次升级，不替代模型对整句语义的理解。用户编辑入口仍可明确设置有依据的长期偏好。

observed_pattern 始终是观察，不因重复变 user_confirmed。单个语境可保存 staged+tentative 候选，不参与召回。发布仍至少需要两个独立会话、非空适用条件和反例审查。独立语境从真实证据归属推导，不接受模型自行编造的数量或 ID；同一会话聊十轮仍只有一个语境。

条件和反例与模式一起保存。反例审查不等于一定存在反例；没有找到时允许证据列表为空，不制造相反陈述凑数。新反例可以用当前 evidence 索引引用；已有有效反例不会因模型下一次省略而消失。已确认偏好不能被自动推断降级。当前条件适用采用文字分词重叠，所有条件都需与 query/近期用户上下文匹配；复杂否定与隐喻仍待真实测试校准。

模式帮助理解表达，不要求角色模仿用户口头禅，不作心理诊断，也不能修改用户管理的主性格。

## 兼容、验证与边界

无需新数据库迁移：阶段一已有三类记录及解释结构，完整载荷继续保存在不可变 revision JSON。六个 MCP 工具和 contract_version 仍为 1.0.0。私有 DeepSeek proposal 新增 optional interpretations/patterns，阶段四已有任务和快照可继续读取。

补齐候选同事务创建 episode 与 response_need 的作用域校验：只有本 patch 新建的 episode ID 可作为 episode scope，不能用任意临时 pattern ID 代替。单记录及交互接口仍校验现存作用域。

验证使用合成多轮、FakeProvider 和原有真实 SQLite 事务，包括逐步倾诉、历史情绪、连续纠正、已确认保护、本次需要更新、跨会话和到期排除、条件模式、同会话不充数、反例保留，以及单次需要不升级长期偏好。反例覆盖未来时间戳、从不同证据拼接时间/回合窗口，以及借其他会话用户依据和当前助手消息激活需要。最终完整检查包含 122 项测试、类型与 Schema 漂移检查、构建及编译后 CLI 备份恢复。

本阶段不添加后台写主设定的接口。用户纠正期间的在途结果仍受 epoch 与版本隔离；同一快照之后的语义重述是否完整保留用户事实，需要真实模型评估，不能仅凭结构校验作出保证。检索索引规模、旧资料归属、无损归档与完整聊天 UI 按后续独立阶段交付。
