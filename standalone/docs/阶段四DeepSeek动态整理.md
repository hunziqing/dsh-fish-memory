# 阶段四：DeepSeek 经历抽取与动态修订

本阶段交付后台 DeepSeek 连接、受校验的紧凑候选、持久上下文快照、连续整理、相邻回合合并、预算、失败重试和独立任务恢复。情绪解释与长期交流习惯在阶段五完善；自有聊天管理页面在阶段八交付。

## 显式启用

默认不调用模型。旧配置没有 deepseek 字段时仍按 disabled 读取；升级不会自动启用付费调用。先停止服务，在 standalone 目录配置：

```powershell
npm run cli -- stop --home '你的独立运行目录'
npm run cli -- configure-deepseek --home '你的独立运行目录' --enabled true --model deepseek-flash --daily-calls 50
```

在启动终端自行设置 `DEEPSEEK_API_KEY`，再执行 serve。密钥不通过聊天提供，不写入 config.json 或仓库；配置只保存环境变量名。可用 --api-key-env 指定本服务专用的变量。没有密钥时服务仍运行、保存回合和任务，状态显示 MODEL_NOT_CONFIGURED，不把它当作已处理。

当前固定官方 `https://api.deepseek.com/chat/completions`，模型名须为 deepseek-*。2026-10-30 核对的官方示例使用 deepseek-flash；可自行选择官方仍支持的 DeepSeek 型号。整理请求为 JSON mode、非流式、显式关闭 thinking；不保存或返回 reasoning_content。

暂停后台整理：停止服务，把 --enabled 改为 false，再启动。configure-deepseek 需要独占运行目录，不在服务运行期间偷偷替换活动配置。停止不会删除记忆或待处理任务。

## 从原话到完整修订

1. observe_turn 的原文与任务先原子落盘。
2. 工作器只在前序原话已连续接收后认领，按分支内回合序号处理。
3. 读取最多配置窗口的完整回合、有限的先前上下文和相关经历，保存不可变 model_contexts 快照。
4. DeepSeek 输出紧凑 JSON 候选，只描述经历、原话区间、日期、关系和修订理由。
5. 服务根据已保存快照分配证据 ID、绑定人物和记忆版本，生成正式 CandidatePatch。模型不能自行指定 job、companion、基础版本或任意来源。
6. 校验 Unicode 码点、逐字原话、角色、时间、来源、版本、租约和上下文 epoch；通过后才在统一事务中发布完整修订并推进处理水位。

已有经历优先沿用稳定 memory_id；新事件由服务分配正式 ID。新原话补充证据，旧理解保留在旧修订。事件拆分/合并可以用多记录候选与关系，旧记录改 disputed；来源撤回仍只由用户专用工具执行。

引用必须来自提供的、活动且未屏蔽的用户消息，助手自己的猜测不能成为用户经历。未知发生时间保持 unknown，不用采集时间填补；日期依据必须映射到本次真实证据。当前不自动新增第三方身份，复杂归属仍需后续人物映射及实际效果验证。

当原话被编辑时，旧理解不再作为事实提供给模型：只保留待重建记录的 ID、版本及必要身份壳，标记 memory_states=needs_rebuild，隐藏旧概要、详情和依赖解释。模型用新原话重建，并可以保留原记忆 ID。撤回来源整轮文本及助手回声在后续模型上下文中留空，明确标记 suppressed；被撤回来源影响的旧正文也不再提供。

## 上下文 epoch 与旧结果隔离

新增 companion_epochs。记忆发布、用户纠正及有效性变化会推进 memory_epoch；每个模型上下文固定其读取时的 epoch。

模型返回后，不只检查它要修改的记录版本，还检查读取快照是否仍有效。用户期间新建偏好、纠正或撤回，即使旧候选改成“创建新 ID”，也会被拒绝并重新读取上下文。空变化决定同样检查，不能用迟到的 none 虚报已处理。

模型调用在 SQLite 写事务外执行。后台定期续租；来源编辑、旧租约失效或停机中止请求。服务关闭等待后台工作结束，不留下独立写库进程。

## 合并窗口与连续水位

默认 window_turns=6，可以把已完整接收的相邻回合合并为一次整理，减少 API 次数。完整原话放不进输入预算时，不截掉关键半句并声称已经处理；当前回合过大则任务明确失败，原文仍在。

每个快照保存 first_sequence 和实际最后覆盖水位。只有落在该范围内、尚未执行的任务才可记为 COALESCED；其状态为 cancelled、结果指向已完成的覆盖任务。连续水位查询会核对覆盖任务确实 completed，再把它计为处理完成。缺口、失败、未覆盖和在途任务仍会阻止水位推进。

原 turn_receipts 不变。新增 turn_processing 保存当前处理任务，负责在显式重试时指向新 job。相同原 observe 请求仍返回最初回执；查询最新状态应看 status 或新请求号的逻辑重复结果。

## 失败、预算与重试

- JSON 结构错误、无依据引文、空输出、网络和限流不提交记忆；按策略有界重试。被截断的模型输出不作为完整 JSON 接受。
- 每次模型请求前，先在数据库预留调用次数与保守 token 额度。默认每日 50 次后台调用，按 UTC 日计数；daily_reserved_tokens 默认 1,500,000。
- 预留估算采用输入字节数、最大输出和固定余量，实际返回的 prompt/completion token 另记。它是应用预算，不是精确账单；失败和中断的请求仍占预留，避免不明计费绕过预算。
- 日预算用尽时，没有发出的请求不会消耗任务尝试次数，等待下一个 UTC 日。超大的原始回合、无效配置和不可重试错误会保留明确失败状态。
- 默认最大三次尝试。终态任务不偷偷变回 running，用户可显式创建新的重试任务：

```powershell
npm run cli -- retry-job --home '你的独立运行目录' --job-id '失败任务ID' --request-id '本次重试的稳定请求ID'
```

该操作需要管理凭据，重复相同请求号不重复生成任务。旧失败任务和原回执保留；成功的新任务可修复连续处理水位。配置或密钥修好后可用此方式恢复。

状态仅返回任务、模型名、用量数字和安全错误类别，不打印远端错误正文、密钥、原话或模型思考。当前用量统计只涉及后台整理，前台聊天尚未启用。

## 迁移与验证范围

新增 004-extraction-worker.sql：epoch、处理任务映射、不可变模型上下文和调用预算账本。旧迁移字节不变。个人库仍在仓库外，备份不含环境密钥；恢复应配套对应版本程序和一致性备份。

`npm run check` 通过全部 112 项测试、类型检查、Schema 漂移检查、编译及编译后 CLI 备份恢复演练。测试使用合成原话、注入的假提炼器或假 fetch，不发起真实付费 API 请求。验证逐轮修订同一经历、合并窗口、乱序缺口、用户纠正期间的旧 create/none、消息编辑、来源撤回脱敏、严格引文、超限、预算、失败新身份重试、拆分整组失败回滚与重试，以及停止清理。

这些测试证明持久化与候选守卫闭环，不证明 DeepSeek 已达到自然语言理解效果。真实抽取的事件关联、否定、人物指代、拆分/合并质量与措辞，仍需要用户后续实际测试和人工评估。
